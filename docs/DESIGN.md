# Design notes

## Palette
| Role | Colour |
|---|---|
| Bodies (page, sidebar, chat) | `#000000` true black |
| Elevation | tiny indigo-black steps `#05040c`, `#0a0818`, `#131029` (never charcoal grey) |
| Accent | cyan `#4fe0ff`, ice `#8fd3ff` |
| Structure (borders, lines) | indigo `#5b4bd6` at 25-100% |
| Meaning only | pink `#ff3d9a` = errors, destructive actions; ember `#ffb45e` = warnings |
| Text | ice-white `#dce8f5`, never pure white |

## Rules
1. **Tokens, not classes.** Override claude.ai's design tokens in three layers: role ramps (`--cds-role-*`), semantic tokens (`--cds-surface-*`, `--cds-text-*`, `--cds-border*`) and a replacement grey ramp (`--cds-gray-*`, `--cds-neutral-*`, generated by `tools/gen-ramp.py`), plus the older HSL variables (`--bg-*`, `--text-*`). Light mode gets the same values.
2. **Ornament only on secondary elements.** Angular cuts (top-left and bottom-right corners) on code cards, dialogs, menus and popovers. Primary surfaces (the reply box, chat column, sidebar, artifact panel) stay plain and square.
3. **No stray details.** A gap, seam, double border or extra outline reads as "a thing" and makes the page busy. The edge on a cut corner follows the diagonal with no gap (code cards: an even-odd `clip-path` frame drawn above the content; dialogs and menus: corner gradients exactly on the cut). Inline code has a fill and no outline.
4. **One shape language.** Buttons and banners use a 2px radius to match the square and angular containers. Switches keep their track shape.
5. **Colour means something.** One accent hue for interaction; pink and ember only for state.

## Known limits
- Artifacts render in a cross-origin iframe and keep their own colours.
- Code tokens coloured by inline styles keep claude.ai's own syntax colours (readable on black).
- The fixture approximates the logged-in DOM; selectors for the reply box and code cards are verified on the fixture.
